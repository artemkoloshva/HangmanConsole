## 📖 О проекте

Учебный pet-проект в рамках курса [`zhukovsd/java-backend-learning-course`](https://zhukovsd.github.io/java-backend-learning-course/). Игра воспроизводит классические правила «[Виселицы](<https://ru.wikipedia.org/wiki/Виселица_(игра)>)»: игроку загадывается случайное русское существительное, и он должен угадать его по буквам до того, как закончатся попытки.

Проект создавался не ради самой игры, а как площадка для практики:

- 🧱 **ООП-декомпозиции** — игровая логика, представление и ввод данных разнесены по отдельным, слабо связанным классам;
- 🧩 **MVC-подобной архитектуры** — отдельные пакеты `model`, `view`, `controller`;
- 🧰 **переиспользуемых абстракций** — обобщённые интерфейсы (`Dictionary<T>`, `Builder<T>`, `Dialog<T>`) и паттерн Builder для меню;
- ☕ **современных возможностей Java** — records, generics, `sealed`-подобная декомпозиция через интерфейсы, text-блоки, а также неявные классы с методом `main()` без явного объявления `class`.

Проект прошёл код-ревью в рамках курса ([`REVIEW.md`](./REVIEW.md)); все отмеченные в нём замечания учтены в текущей версии.

## 🛠️ Стек технологий

- **Язык:** Java 21+ (используются records, generics, text-блоки, неявные классы и `void main()` без обёртки `class` — [JEP 445/463/477/512](https://openjdk.org/jeps/512))
- **Парадигма:** ООП с элементами функционального стиля (`Function`, `Predicate`, `Runnable` как поведение, передаваемое в конструкторы)
- **Архитектура:** MVC-подобное разделение `model` / `view` / `controller`
- **Сборка:** без систем сборки (Maven/Gradle не используются) — чистый Java, компилируется `javac`
- **Ввод/вывод:** консоль, `java.util.Scanner`
- **Данные:** словарь слов хранится в текстовом файле (`dictionary.txt`), читается построчно
- **Зависимости:** только стандартная библиотека JDK, внешние библиотеки не используются

## 🕹️ Как играть

1. При запуске показывается главное меню:
   ```
   Добро пожаловать в консольную игру "Виселица"!
   1. Новая игра
   2. Выйти из игры
   ```
2. Пункт меню выбирается вводом номера — ввод проверяется, чтобы номер попадал в допустимый диапазон.
3. При выборе «Новая игра» из словаря случайно выбирается слово, и начинается раунд:
   - на экран построчно выводится текущее состояние виселицы (ASCII-арт), маска слова (`_ _ _ ...` с открытыми буквами) и список ошибочных букв;
   - игрок вводит одну русскую букву (а–я, ё) — ввод любых других символов не принимается, и диалог просит повторить ввод;
   - если буква уже вводилась ранее, игра сообщает об этом отдельным сообщением и не тратит попытку впустую.
4. Игра заканчивается:
   - **победой** — когда все буквы слова открыты;
   - **поражением** — когда количество ошибок достигает лимита (в игре **6 ошибок**, что соответствует 7 стадиям прорисовки виселицы, от пустой рамки до полностью «повешенного» человечка); при поражении на экран выводится загаданное слово.
5. После завершения раунда игра возвращается в главное меню — можно сыграть снова или выйти.

## 🏗️ Архитектура

Проект разделён на пакеты, приближённые к **MVC**:

```
com.github.artemkoloshva/
├── model/                  → игровые данные и правила (не зависят от способа вывода)
│   ├── game/                  Game, SecretWord — состояние и правила одного раунда
│   ├── menu/                  Menu, MenuItem — модель меню
│   ├── dictionary/            Dictionary<T>, FileDictionary — источник случайных слов
│   ├── common/                Builder<T>, MenuBuilder — обобщённый паттерн Builder
│   └── GameConstants          константы игровых правил (лимит ошибок)
├── view/                    → весь вывод в консоль и диалоги ввода
│   ├── dialog/                 Dialog<T>, ConsoleDialog<T> и его наследники — переиспользуемые диалоги ввода/валидации
│   ├── GameView, MenuView      вывод состояния игры и меню
│   ├── HangmanAscii            ASCII-рисунки виселицы по стадиям
│   └── ViewMessages            текстовые константы сообщений
├── controller/              → связывает модель и представление
│   ├── GameController          игровой цикл одного раунда
│   └── MenuController           цикл главного меню
└── util/
    └── Constants                прочие технические константы (путь к словарю и т.п.)

Main.java  → точка входа (в корне, без пакета)
```

### Ключевые классы и их назначение

| Класс | Пакет | Назначение |
|---|---|---|
| `Game` | `model.game` | Состояние раунда: использованные буквы, маска слова, подсчёт ошибок, определение победы/поражения |
| `SecretWord` | `model.game` | Обёртка над загаданным словом, проверка наличия буквы |
| `GameConstants` | `model` | Лимит допустимых ошибок |
| `Menu` / `MenuItem` | `model.menu` | Модель меню: заголовок и пункты (`MenuItem` — record с текстом пункта и действием) |
| `Dictionary<T>` / `FileDictionary` | `model.dictionary` | Абстракция источника слов и её файловая реализация |
| `Builder<T>` / `MenuBuilder` | `model.common` | Обобщённый интерфейс билдера и его реализация для сборки `Menu` в fluent-стиле |
| `Dialog<T>` / `ConsoleDialog<T>` | `view.dialog` | Абстракция диалога ввода: принимает `Function` (парсинг) и `Predicate` (валидацию), повторяет запрос до корректного ввода |
| `RussianLetterDialog` | `view.dialog` | Диалог ввода одной русской буквы |
| `IntegerMinMaxDialog` | `view.dialog` | Диалог ввода числа в заданном диапазоне (используется для выбора пункта меню) |
| `StringSelectDialog` | `view.dialog` | Диалог выбора строки из списка допустимых значений (готовая переиспользуемая абстракция) |
| `GameView` / `MenuView` | `view` | Вывод состояния игры / меню в консоль |
| `HangmanAscii` | `view` | ASCII-арт виселицы по стадиям (0–6 ошибок) |
| `ViewMessages` | `view` | Текстовые константы сообщений игры |
| `GameController` | `controller` | Игровой цикл: связывает `Game` и `GameView` |
| `MenuController` | `controller` | Цикл главного меню: связывает `Menu` и `MenuView`, запускает выбранное действие |
| `Constants` | `util` | Путь к файлу словаря и прочие технические константы |
| `Main` | (без пакета) | Точка входа: собирает меню через `MenuBuilder`, создаёт зависимости и запускает `MenuController` |

### Используемые приёмы и паттерны

- **Dependency Injection через конструктор** — `GameController` и `MenuController` не создают свои зависимости сами, а получают уже готовые `Game`/`Menu` и `View` снаружи (собирается всё в `Main`).
- **Builder** — `Menu` собирается через `Menu.addTitle(...).addItem(...).addItem(...).build()`.
- **Обобщённый (generic) диалог ввода** — `ConsoleDialog<T>` не завязан на конкретный тип данных: логика парсинга и валидации передаётся снаружи через `Function<String, T>` и `Predicate<T>`, а конкретные диалоги (`RussianLetterDialog`, `IntegerMinMaxDialog`, `StringSelectDialog`) лишь параметризуют базовый класс.
- **Record** — `MenuItem` реализован как immutable record.

## 🚀 Запуск проекта

Проект не использует системы сборки — это чистый Java-проект на `javac`/`java`.

> ⚠️ Файл `Main.java` использует неявные классы и метод `main()` без обёртки `class` (JEP 445/463/477, финализировано в JEP 512) — эта возможность доступна начиная с **Java 21** (в более старых версиях JDK как preview-фича, требующая флага `--enable-preview` и `--release <версия>`) и стабильна без флагов, начиная с **Java 25**. Убедитесь, что используете подходящую версию JDK.

### Вариант 1 — через IDE

1. Откройте проект в IntelliJ IDEA (или другой Java IDE) с установленным JDK 21+.
2. Укажите папку с исходниками как **Sources Root**.
3. Запустите `Main.java`.

### Вариант 2 — из терминала

```bash
git clone https://github.com/artemkoloshva/HangmanConsole.git
cd HangmanConsole

# Компилируем все исходники (для JDK < 25 может понадобиться --enable-preview --release 21)
javac -d out $(find src -name "*.java")

# Запускаем игру из корня проекта — важно для корректного пути к словарю
java -cp out Main
```

> 💡 Путь к словарю (`Constants.DICTIONARY_PATH`) задан в коде как относительный путь в Windows-стиле (`src\com\github\artemkoloshva\resources\dictionary.txt`). На Linux/macOS обратный слэш не воспринимается как разделитель каталогов, поэтому для запуска на этих системах путь нужно адаптировать под `/`, либо запускать проект на Windows/из IDE, которая сама резолвит рабочую директорию корректно.
