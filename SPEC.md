# Проект «Виселица»

## Описание задачи
Реализовать консольную игру «Виселица» на языке Java. Правила игры описаны в [Википедии](https://ru.wikipedia.org/wiki/Виселица_(игра)).

## Необходимые знания
- Базовый синтаксис Java.

## Цель проекта
Проект носит разминочный характер и предназначен для проверки готовности к переходу от решения отдельных задач к разработке полноценных приложений. При наличии опыта реализации подобных проектов данный этап можно пропустить.

## Функциональные требования

1. **Главное меню**: при запуске пользователю предлагается начать новую игру или завершить работу приложения.
2. **Игровой процесс**:
   - Система случайным образом выбирает слово из словаря.
   - Пользователь вводит буквы для отгадывания слова.
   - После каждого ввода отображается текущее состояние виселицы (ASCII-графика) и счетчик ошибок.
3. **Завершение раунда**: при победе или поражении выводится результат, после чего управление возвращается в главное меню.

## Рекомендации по архитектуре
- Точка входа — метод `main` одного из классов.
- При наличии навыков объектно-ориентированного программирования рекомендуется разделить логику на несколько классов.
- При отсутствии опыта ООП допускается процедурный стиль реализации через статические методы основного класса.

## План реализации
1. Подготовить словарь существительных в именительном падеже, исключив слова недостаточной длины.
2. Реализовать основной игровой цикл (ввод данных, проверка условий, обновление состояния интерфейса).
3. Реализовать цикл повторения игры (возврат в меню после завершения раунда).

## Чеклист самопроверки

**Внимание:** ознакомление с данным разделом рекомендуется только после написания первой рабочей версии кода.

### Функциональные аспекты
- Отсутствие валидации ввода (допустимы только строчные буквы кириллицы). Некорректный ввод не должен увеличивать счетчик ошибок.
- Повторный ввод неверной буквы не должен засчитываться как новая ошибка.

### Качество кода
- Использование коллекций (`List`, `Set`) вместо массивов.
- Использование относительных путей к файлу словаря вместо абсолютных.
- Декомпозиция кода: один метод отвечает за одну логическую задачу (например, открытие угаданной буквы в маске слова).
- Минимизация использования глобальных переменных (`public static` полей).
- Семантически корректное именование переменных, методов и полей.
- Использование цикла для перезапуска игры вместо рекурсивных вызовов.

### Технические детали
- Наличие файла `.gitignore` для исключения служебных директорий (`target`, `out` и др.) из системы контроля версий.
- Соблюдение стандартов форматирования кода.
